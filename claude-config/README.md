# Shared Claude config (baked into the image)

Anything in this directory is copied into `/root/.claude/` inside the
agent + code-server images at build time. Edit a file here, push, CI
rebuilds, every hive worker (desktop, VPS, future laptop) picks it up
on the next image pull.

## What to put here

- `CLAUDE.md` — global rules every Claude Code session inherits
- `skills/<skill-name>/SKILL.md` — custom skills you want shared
- `commands/<cmd-name>.md` — custom slash commands

## What NOT to put here

This directory is in a **public-by-default** git repo:

- ❌ `.credentials.json` / OAuth tokens — generated by `claude login`,
  per-host, per-volume
- ❌ `sessions/` / `projects/` / `history.jsonl` — your private
  conversation state
- ❌ `settings.json` if it contains MCP server credentials or any keys
- ❌ `plans/` — per-conversation plan files (likely contain sensitive
  context)
- ❌ Anything with API keys, tokens, customer data

## How OAuth still works

`claude login` is a **one-time per host** action. The OAuth token lands
in `/root/.claude/.credentials.json` on a mounted volume:

- Desktop: bind-mount `C:/Users/djohn/.claude:/root/.claude` — your
  host login is the container's login automatically
- VPS: named volume `claude-data:/root/.claude` — on first boot Docker
  seeds the volume from the image's baked content, then `claude login`
  once writes the token, persists across image upgrades

Sharing one OAuth token across hosts isn't supported by Anthropic and
risks tripping anomaly detection on the subscription account.
